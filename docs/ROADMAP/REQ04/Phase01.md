# REQ04-Phase01 자료 대조와 사례 구성 확정

[로드맵의 Phase 상태](../../ROADMAP.md) · [요구사항](../../REQUIREMENTS/REQ04.md) · [콘텐츠 설계](../../SPEC/REQ04/content-architecture.md) · [완료 조건](../../GOAL/REQ04/Phase01.md)

## 목적

글을 쓰기 전에 독자에게 보여줄 주장, 코드·Git·검증 근거, 화면과 그림을 사례별로 확정한다. 이 단계는 공개 페이지를 구현하거나 원본 프로젝트를 수정하지 않는다.

## 작업 순서

1. [자료 인덱스](../../portfolio/maple-insight/README.md)에서 네 사례에 필요한 문서·이미지를 고른다. 기존 REQ03 글과 중복되는 구조 발전 설명은 링크로 대체할 부분을 정한다.
2. 원본 `~/projects/maple_repo`의 `api-types` 4파일 구조·상위 export, Raw→내부 Contract 매퍼, `@maple/db`·`@maple/data-admin`, Prisma 스키마, Electron IPC·서비스와 Git 기록을 주장 단위로 대조한다. 공식 API 명세와의 일치가 필요한 화면은 발행 시점에 재확인한다.
3. Electron 화면마다 담당 GOAL/REVIEW의 검증 수준과 실제 코드 경로를 연결한다. DB ERD·아키텍처 PNG에 현재 코드보다 넓은 주장이 있으면 캡션을 제한하거나 대체 그림으로 만든다.
4. 프로젝트 페이지 요약과 API·DB·Electron 각 글의 제목, 섹션 순서, 그림·스크린샷 선택, 양방향 링크를 검토 가능한 콘텐츠 개요로 정한다. 각 주장에 **구현 완료 / 부분 구현 / 계획 / 확인 필요** 표기를 붙인다.
5. 공개 이미지의 출처·촬영 날짜·민감 정보 및 모바일 가독성을 확인한다. 확인되지 않은 자산은 사용 보류로 기록한다.

## 다음 단계로 넘길 결과

- 대표 주장·근거·상태를 묶은 사례별 개요와 자산 선택 목록.
- 공개 전에 해결할 불일치·미확인 항목 목록.
- 프로젝트 페이지와 기존 설계 변화 글에서 새 사례로 이동할 링크 설계.

Phase 완료 여부는 [GOAL](../../GOAL/REQ04/Phase01.md)의 조건과 향후 REVIEW 근거로 판단한다. 다음 Phase의 공개 글 작성·UI 연결은 로드맵의 순서를 따른다.
