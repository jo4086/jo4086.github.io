# REQ04-Phase02 기술 사례 작성과 연결

[로드맵의 Phase 상태](../../ROADMAP.md) · [요구사항](../../REQUIREMENTS/REQ04.md) · [콘텐츠 설계](../../SPEC/REQ04/content-architecture.md) · [선행 Phase](./Phase01.md)

## 선행 조건

REQ04-Phase01의 사례별 개요, 주장·근거·상태 표, 공개 자산 선택을 검토하고 미확인 항목의 처리 방식을 정한다. 그 결과를 바탕으로 이 단계의 상세 GOAL을 작성한다.

## 작업 순서

1. 프로젝트 상세 페이지에 설계 변화 글과 세 기술 사례의 짧은 입구를 추가한다. 기존 읽기 흐름과 목차·반응형 구조를 유지한다.
2. API 타입 글에서 표준 4파일 구조와 Raw→내부 Contract 경계, 공식 문서·기존 예시를 이용한 **수동 요청 기반** 추가 과정을 보여준다.
3. DB 글에서 `@maple/db`와 `@maple/data-admin`의 책임, 네 PostgreSQL 스키마와 선택한 대표 관계를 설명한다.
4. Electron 글에서 웹 관리자와 로컬 도구의 책임, IPC 경계, 버전 비교·직업·스킬 화면의 검증된 동작을 시간 순서로 설명한다.
5. 선택한 이미지를 공개 자산으로 준비하고 캡션·대체 설명·출처를 붙인다. 글 ↔ 프로젝트 소개 ↔ 기존 설계 변화 글의 링크를 연결한다.

## 산출물과 경계

기존 사이트 구조에 맞춘 프로젝트 소개의 연결과 세 개의 기술 사례 글이 산출물이다. 각 글은 완료·부분 구현·계획을 분리한다. 원본 Maple Insight 코드 수정, API 추가, 새로운 자동 동기화, 개별 PDF 제작, 배포는 이 단계의 산출물이 아니다.

구현을 시작할 때는 [프로젝트 지침](../../../AGENTS.md)의 코드·UI 검증을 적용하고, 테스트와 화면 확인 결과를 REVIEW에 남긴다. Phase 상태는 [로드맵](../../ROADMAP.md)에서만 바꾼다.
