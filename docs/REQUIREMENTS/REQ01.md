# REQ01 포트폴리오와 블로그 UI

## 목적과 범위

한 정적 사이트에서 개발자 포트폴리오와 개인 블로그를 탐색하고 읽을 수 있게 한다. [UI 흐름 예시](../../screenshots/manual/portfolio-blog-ui-flow.png)는 화면 구성의 참고 자료이며 픽셀 단위의 구현 기준은 아니다. 구체적인 화면 규칙은 [UI SPEC](../SPEC/REQ01/ui.md)을 따른다.

## 요구사항과 수용 기준

- **REQ01-01 공통 탐색:** Home, Projects, Blog, About으로 이동할 수 있고 현재 페이지를 식별할 수 있다.
- **REQ01-02 포트폴리오:** Home에 개발자 소개와 두 영역의 진입 링크가 있고, 프로젝트 목록은 기술 필터·이미지·이름·요약을 제공한다. 프로젝트 상세에는 개요, 기술, 기능, 이미지, 구조, 문제 해결, 관련 글과 외부 자료를 표시할 수 있다.
- **REQ01-03 블로그 목록:** 검색, 전체·최근 글, 접을 수 있는 계층형 카테고리, 태그, 아카이브를 제공한다. 분류와 항목 수는 게시글 데이터에서 계산하며 이미지가 없는 글도 읽기 쉽다.
- **REQ01-04 게시글 상세:** 제목·메타데이터·Markdown 본문·목차를 제공한다. 목차 항목을 선택하면 해당 제목으로 이동한다.
- **REQ01-05 반응형·접근성:** 넓은 화면에서는 필요한 보조 탐색을 함께 제공하고, 좁은 화면에서는 본문 너비를 우선하며 사이드바와 목차를 접근 가능한 방식으로 접는다. 접기·펼치기는 즉시 적용한다.
- **REQ01-06 데이터와 연결:** 프로젝트와 게시글 데이터를 구분하고 slug로 상호 연결한다. 카테고리·태그·아카이브는 Markdown frontmatter에서 유도한다.
- **REQ01-07 검증:** `pnpm check`, `pnpm build`와 데스크톱·모바일 Playwright 탐색 검증을 통과하고 화면을 직접 확인한다. 의존성을 변경하면 `pnpm check:deps`도 통과한다.

## 제약

- GitHub Pages 정적 사이트와 React Router v7 `HashRouter` 결정을 유지한다.
- 백엔드, 데이터베이스, CMS, 배포 자동화는 이 요구사항의 범위 밖이다.
- 실제 개인 이력이나 프로젝트 성과를 임의로 만들지 않는다. 확인되지 않은 콘텐츠는 예시로 구분한다.
