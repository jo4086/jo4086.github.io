# REQ04-Phase01 완료 조건: Maple Insight 기술 사례의 근거와 개요

[로드맵](../../ROADMAP.md) · [Phase 계획](../../ROADMAP/REQ04/Phase01.md) · [요구사항](../../REQUIREMENTS/REQ04.md) · [콘텐츠 설계](../../SPEC/REQ04/content-architecture.md)

- [x] API 타입, DB, Electron 사례마다 문제·설계 판단·대표 코드·검증 결과·남은 범위의 개요를 작성하고 근거 링크를 연결한다. [작성 개요](../../SPEC/REQ04/case-outline.md) · [검증 기록](../../REVIEW/REQ04/Phase01.md).
- [x] `api-types`의 4파일 규칙과 export 구조, Raw→내부 Contract 경계를 실제 코드로 확인한다. 신규 API 추가의 수동 시작과 자동 동기화의 부재를 명시한다. [검증 기록](../../REVIEW/REQ04/Phase01.md).
- [x] `@maple/db`·`@maple/data-admin`·Prisma 스키마의 역할과 대표 관계를 코드·ERD와 대조하고, 그림의 과장 가능성을 기록한다. [검증 기록](../../REVIEW/REQ04/Phase01.md).
- [x] Electron IPC·DB·파일 경계와 선택할 화면의 동작 범위를 담당 GOAL/REVIEW·코드와 대조해 완료·부분 구현·계획을 구분한다. [검증 기록](../../REVIEW/REQ04/Phase01.md).
- [x] 공개할 이미지의 출처·시점·민감 정보·모바일 가독성을 확인하고, 사용할 것과 보류할 것을 결정한다. [이미지 선택](../../SPEC/REQ04/case-outline.md) · [모바일 확인](../../REVIEW/REQ04/Phase01.md).
- [x] 프로젝트 소개, 기존 설계 변화 글, 새 사례 사이의 이동 경로와 중복을 검토한다. [작성 개요](../../SPEC/REQ04/case-outline.md).
- [x] 미확인 주장과 공개 전 결정할 항목을 남기고 검토 결과를 REVIEW에 기록한다. [검증 기록](../../REVIEW/REQ04/Phase01.md).

이미지의 촬영자·촬영일과 Electron 화면별 DB·로컬 파일 경계, 모바일 표시 방식을 확인했다. 공식 명세·공개 URL의 발행 시점 재확인은 [Phase03](../../ROADMAP/REQ04/Phase03.md)에 남긴다.
