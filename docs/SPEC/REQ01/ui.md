# REQ01 UI SPEC

[요구사항](../../REQUIREMENTS/REQ01.md)의 REQ01-01~07을 구체화한다. [예시 이미지](../../../screenshots/manual/portfolio-blog-ui-flow.png)는 정보 구조와 흐름을 참고하는 자료다.

## 화면 구성

| 경로              | 구성                                                                                  |
| ----------------- | ------------------------------------------------------------------------------------- |
| `/`               | 짧은 소개, 개발 주제, Projects와 Blog 진입 링크. 큰 장식 카드 없이 콘텐츠를 우선한다. |
| `/projects`       | 기술 필터와 프로젝트 이미지·이름·요약 목록. 선택 시 상세로 이동한다.                  |
| `/projects/:slug` | 개요, 기술, 주요 기능과 이미지, 구조, 문제 해결, 관련 글 및 외부 링크.                |
| `/blog`           | 탐색 사이드바와 게시글 목록. 제목·요약·날짜·카테고리를 중심으로 표시한다.             |
| `/blog/:slug`     | 글 메타데이터, Markdown 본문, 본문 제목에서 파생한 목차.                              |
| `/about`          | 소개와 관심사, 연락·외부 링크를 한 열로 표시한다.                                     |
| `*`               | 알 수 없는 경로 안내와 복귀 링크.                                                     |

공통 헤더는 네 경로를 `NavLink`로 제공한다. 각 화면은 하나의 `main` 랜드마크를 사용한다. `layouts/`가 공통 구조를, `pages/`가 경로별 조합을 소유한다. 기능별 UI와 데이터 처리는 각각 `features/portfolio/`, `features/blog/`에 둔다.

## 블로그 탐색과 콘텐츠

- 사이드바 순서는 검색, 전체 글, 최근 글, 카테고리, 태그, 아카이브다. 최근 글은 최신순 일부를 보여준다.
- frontmatter의 `category`는 계층 경로, `tags`는 문자열 배열이다. 유효한 게시글만 분류·건수 계산에 포함한다. 빈 분류는 표시하지 않는다.
- 카테고리는 버튼으로 즉시 접고 펼친다. 필터·검색은 URL 쿼리에 저장해 공유·뒤로 가기를 지원한다. 검색 대상은 처음에는 제목·요약·태그다.
- 게시글에는 이미지가 필수가 아니다. 있으면 목록에 작은 이미지로 표시하고, 없으면 글 정보가 전체 너비를 사용한다.
- Markdown `h2`·`h3`에서 고유 ID와 목차를 만든다. 목차 선택 시 해당 제목으로 스크롤하고 초점을 이동한다. `HashRouter`와 충돌하는 두 번째 URL 해시는 사용하지 않는다.
- 프로젝트 데이터의 `relatedPostSlugs`와 글의 `relatedProjectSlugs`는 각각 선택적이다. 유효한 대상만 링크한다.

## 반응형 동작

- 넓은 데스크톱에서는 블로그 상세의 왼쪽 탐색·본문·오른쪽 목차를 함께 둔다. 본문은 읽기 편한 너비를 우선한다.
- 공간이 부족해지면 목차를 먼저 글 위의 접이식 목록으로 옮기고, 그다음 탐색 사이드바를 드로어로 전환한다.
- 모바일에서도 공통 경로와 블로그 탐색·목차에 접근할 수 있다. 드로어는 닫기, Escape, 초점 복귀를 지원한다.
- 문서 전체 스크롤을 사용하고, 불필요한 높이 제한이나 전환 애니메이션을 두지 않는다.

## 콘텐츠 형식

게시글은 `src/content/posts/*.md`의 frontmatter에 `slug`, `title`, `date`, `summary`, `category`, `tags`를 둔다. 프로젝트는 별도 TypeScript 데이터로 관리한다. 목록과 상세는 같은 데이터 원본을 사용한다. 실제 사용자 이력은 확인되지 않았으므로 초기 콘텐츠는 예시로 표시한다.
