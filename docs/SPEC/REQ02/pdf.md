# REQ02 PDF 명세

[REQ02-01·02·05·06·08](../../REQUIREMENTS/REQ02.md)를 구체화한다. [참고 PDF](../../../screenshots/manual/resume-design-reference.pdf)는 이름·연락처 → About Me → Skills → Projects → 개발 워크플로의 순서와 넉넉한 여백을 참고하는 자료다.

## 읽기 구조

| 영역 | 담을 내용 | 길이 기준 |
| --- | --- | --- |
| 상단 | `jo4086`과 GitHub 링크. 이메일·전화번호는 표시하지 않음 | 한눈에 식별 가능한 한 줄 또는 두 줄 |
| About Me | 개발 관심사와 작업 방식 | 2~3문장 |
| Skills | 실제 프로젝트에서 사용한 기술을 역할별로 묶음 | 기술 이름 나열보다 활용 맥락 우선 |
| Projects | Maple Insight, Codex Workspace 각각 문제·설계 판단·현재 결과·상세 링크 | 프로젝트당 짧은 문단과 핵심 2~3줄 |
| 마무리 | 근거를 확인할 수 있는 블로그 주소 | QR 코드 없이도 입력 가능한 텍스트 URL |

한 페이지 A4 세로를 기본 목표로 한다. 글을 줄여 의미가 사라지면 2페이지를 허용한다. 기술 스택, 성과, 링크를 읽을 수 있는 크기로 유지한다.

## 프로젝트 카드의 내용

- **Maple Insight:** 게임 데이터를 조회하고 버전별로 관리해야 하는 이유, 원본 보존·검증·비교의 설계, Electron Data Studio의 확인된 단계와 진행 중인 단계. [사실 자료](../../portfolio/maple-insight/status-and-gaps.md).
- **Codex Workspace:** 개발 지침을 찾기 쉽게 나누는 문제, Skill 라우팅과 Git 커밋 형식 검증, 실제 설치 여부와 구분된 소스 수준의 결과. [사실 자료](../../portfolio/codex-workspace/quality-and-limitations.md).
- 두 프로젝트 모두 AI를 활용한 개인 프로젝트다. Maple Insight의 앱·패키지 구조에 대한 작성자 판단과, 그 개발 경험이 Codex Workspace로 이어진 이유를 간결하게 연결한다.
- 수치나 강한 성과 표현은 근거가 확인된 경우에만 넣고, 본인 기여를 확인하기 전까지 팀 전체의 결과를 개인 성과로 쓰지 않는다.

## 링크와 파일 품질

- 프로젝트 이름과 `자세히 보기` 텍스트를 각각 해당 상세 페이지 URL에 연결한다. 링크의 표시는 읽기 쉬운 텍스트로 하며 색상에만 의존하지 않는다.
- PDF 내부 URL은 배포된 `https://jo4086.github.io/#/projects/...`를 사용한다. `HashRouter`의 `#` 뒤 경로가 PDF 생성 과정에서 잘리지 않아야 한다.
- 출력 파일은 텍스트 선택·복사가 가능하고, 스크린 리더의 제목·본문 순서가 자연스러워야 한다. 링크 주석이 실제로 포함됐는지 PDF 자체에서 검사한다.
- 화면·인쇄 미리보기에서 잘림, 대비, 링크 가독성을 확인한다. 파일명과 다운로드 위치는 구현 단계에서 사이트 내 탐색과 함께 정한다.

## 미정 선택

추가 개인정보와 사진은 사용하지 않는다. 색상·폰트는 사이트의 기존 시각 언어와 맞추며, 특정 PDF 라이브러리를 요구하지 않는다.
